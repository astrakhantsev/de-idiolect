This concept names the accuracy bar that a proposed estimating tool must clear for building it to be worthwhile in the first place. It is used when a project is deciding, in advance of any construction, whether to invest in a tool that would output a single number — a count or multiplier feeding a later judgment — or to fall back on a fixed default value borrowed from experience. The input to the decision is a stated level of typical error for the hypothetical tool, obtained by assumption or by simulating a tool of that accuracy, not by running a finished tool. The concept asserts that benefit degrades with error in tiers: small typical error preserves nearly all of the achievable gain, moderate error preserves roughly half, and beyond a known level the tool's output becomes actively harmful, because a confidently wrong number does more damage than admitting ignorance. The rule is therefore a bar-clearing rule: commit to building the tool only if its expected accuracy clears the bar. Applied before construction, it converts a vague "would this help?" into a checkable condition on error size.
