## P1 — fidelity-judge calibration (false-positive rate)

**Question.** The frozen fidelity gate killed the e2e primary 2/2 but has never been shown to PASS a faithful definition. Can it pass definitions faithful by construction, and does it detect planted defects? **Scope (review F2): this is an author-constructed sanity check on the gate, not a calibration study** — n=4 author-written faithful definitions bound the gate's non-degeneracy, they do not estimate a population FP rate; the faithful labels are the author's own construction against the checklist, not independently adjudicated.

**Materials — already authored at spec time, frozen by hash in the freeze manifest (review F1): `eval/measurements/p1-fidelity-calibration/definitions/{A1..A4,S-a..S-e}.md`, provenance table in `materials.md`.**
- Faithful arm, n=4: A1 terse plain (3 sentences); A2 verbose plain (6 sentences); A3 notation-heavy (simple symbols, no named methods); A4 procedural input/output style. Each explicitly satisfies items i–iv (including prospectivity stated outright), adds no unsupported specifics (v), names no field/method/person/acronym (vi).
- Seeded-defect arm, n=5, each with ONE planted violation (base provenance: S-a = A1 restructured retrospective; S-b = new prospective base with smooth benefit; S-c = A1-like base with inverted rule; S-d = A1 + one inserted name clause; S-e = A1 + one inserted specifics clause): S-a drops prospectivity (frames the decision as checking an already-produced estimate — the drift the e2e observed); S-b removes threshold structure (benefit varies smoothly, no bar); S-c inverts a polarity (build only when error EXCEEDS the bar); S-d adds external method/author names NOT on the leak-checker lists ("Neyman–Pearson", "signal detection" — targets item vi, which exists precisely because the greps can't catch unlisted names); S-e adds unsupported metric/benchmark specifics ("percentage error below 15 percent", "ten thousand labeled cases" — targets item v).
- **Expected-verdict matrix, all items pre-registered (review F3).** A1–A4: i–iv PRESERVED, v PASS, vi empty. S-a: iii NOT-PRESERVED, rest clean (precedent: the e2e judge scored the drifted D-sonnet's item i PRESERVED, so the retrospective reframe is expected to fail iii only). S-b: iv NOT-PRESERVED, rest clean. S-c: iv NOT-PRESERVED, rest clean. S-d: vi non-empty, rest clean. S-e: v UNSUPPORTED-ADDITION, rest clean, with vi listed as acceptable-secondary ("percentage error" may be read as a named metric). Single-violation status is author-asserted; deviations of NON-planted items from this matrix are reported as judge noise (exploratory).

**Procedure.** All 9 leak-checked with `leakcheck_e2e.sh` before freeze — done, 9/9 CLEAN (`runs/leakcheck.log`); a faithful-arm hit would have been fixed at authoring time (logged), a seeded stimulus tripping the checker would have been revised before freeze, never during execution. Judge = frozen config, one isolated opus call per definition, blind to arm and to the existence of a calibration study; run order = ascending sha256(definition file). Per-item verdicts archived.

**Pre-registered endpoints.**
1. FP rate = faithful-arm definitions failed under the frozen failure rule (any of i–iv not PRESERVED, v violated, or vi non-empty) / 4. A conservative-FAIL from malformed JSON counts as a failure (it would have in the e2e).
2. Seeded-arm detection rate = defective definitions failed / 5; item attribution = failures where the planted item is among the failed items / 5.

**Interpretation table (written before running, applied without relitigating; wording bounded per review F2 — no outcome here "calibrates" the gate).**
| outcome | reading |
|---|---|
| FP 0/4 AND detection ≥4/5 | the gate passes author-constructed faithful definitions and catches planted defects; the e2e null survives its most attackable objection on this check (harshness caveat DOWNGRADED to the author-adjudication limit, not removed) |
| FP 0/4 AND detection ≤3/5 | gate can pass faithful definitions but is blunt on defects; e2e failures stand, production design needs a sharper judge |
| FP 1/4 | borderline harshness; caveat sentence in results; flag for entry track as "judge harshness uncertain" |
| FP ≥2/4 | judge-harshness caveat MANDATORY; the e2e "fidelity is the binding constraint" claim is flagged for the entry track (entry not edited) |

Exploratory (labeled): per-item FP structure — specifically whether any faithful-arm failure lands on (iii) prospectivity, the item that killed the e2e primary; and non-planted-item deviations from the expected-verdict matrix (judge noise).

## P2 — checklist-guided generation (the proposed fix)

**Question.** The e2e results doc proposes fidelity as a generation-time component. Does appending an extracted checklist to the frozen D prompt lift the gate pass rate above the e2e baseline of 0/2? Secondary: is checklist EXTRACTION easier than definition compression (the e2e's failure mode)?

**Step 1 — checklist extraction.** One isolated sonnet call: the C2 excerpts + "List the 4–6 structural commitments any faithful definition of this concept must preserve, as short testable items. Use only ordinary plain-English words plus simple notation. Do NOT use any names of people, fields, disciplines, methods, or acronyms. Do NOT reuse any specialized term the notes use as the project's own label for the concept. Return only the numbered list." (constraint block mirrors the frozen prompt-D so the checklist can be appended without smuggling terms). Leak-check the checklist; on a hit, ONE regeneration (fresh sample, same prompt); 2 leaking attempts → step 1 FAILS, reported, P2 stops. Informal fidelity report (author-adjudicated, exploratory): map extracted items onto frozen human items i–v — covered / missed / extra.

**Step 2 — guided generation.** Two configs (sonnet, opus), isolated: frozen `prompt-D.md` text + "The definition must additionally preserve each of these structural commitments:" + the extracted checklist + the same NOTES block. Leak-check per e2e rules (hit → full regeneration, max 3, then config FAILS). Surviving definitions → the frozen fidelity gate (one isolated opus call each, standard input format).

**Pre-registered endpoint (attribution bounded per review F4).** Gate pass count out of 2 guided configs, reported NEXT TO the e2e cell's 0/2 unguided count (same prompts, corpus, isolation machinery, run one day earlier; still a historical comparison with n=1 per config — no contemporaneous unguided replicate, so NO causal "the checklist lifts the pass rate" claim at any outcome). 2/2 or 1/2 = consistent with the fix helping on this cell, stated exactly that weakly; 0/2 = the fix as specified does not clear the gate here — reported as such. Sampling variation at n=1 per config is an explicit limit either way.

**Prompt assembly (review F1, exact):** the guided prompt = full frozen `prompt-D.md` text, then one blank line, then the line "The definition must additionally preserve each of these structural commitments:", then the extracted checklist verbatim, then one blank line, then "NOTES:", then the C2 excerpts verbatim (same NOTES block as the e2e D calls). Every rendered prompt is archived under `p2-guided-generation/runs/inputs/` before its call.

**Exploratory (labeled).** Retrieval ranks of any PASSING definitions on the frozen corpus (same model/serialization as `retrieve.py`; new script in `eval/measurements/p2-*/`, frozen corpus untouched) vs the e2e arms (D-opus rank 1, D-sonnet rank 2, N rank 2). Also: whether the extracted checklist contains prospectivity at all (bears on "is the drift attributable to compression or to the excerpts' emphasis").

**Circularity note (stated limit).** The same frozen human checklist both defines the gate and inspired the fix; the extracted checklist is generated from the same excerpts the judge reads. P2 measures whether the pipeline can satisfy its own gate, not external validity.

## P3 — provenance-verification yield

**Question.** What fraction of model-proposed owner citations survive primary-source verification? (C4's yield; prior anecdotes — 2-for-2 defective citations on audited kills, 5 fabrications — predict attrition; a rate replaces the anecdote.)

**Candidate universe (pre-registered; file set frozen by manifest per review F5).** Every owner-candidate citation OCCURRENCE in `10_projects/minelit/idiolect/def-naming-raw/out-*.md` and `recall-backtest-raw/out-*.md` (file list + sha256 frozen in `p3-provenance/input-manifest.txt` at freeze), plus the e2e F baseline output (`eval/e2e-cell/runs/f-output.txt` — contains only record IDs, so contributes 0 candidates; stated for completeness). Owner-candidate = a specific published work (identifiable by authors + title, or authors + venue + year) proposed as a canonical/owning/oldest treatment of, or direct prior art for, a concept under discussion. Excluded: bare field names, person names with no work attached, works mentioned only as the project's own artifacts. Model-hedged citations ("I'm not sure of the venue") are INCLUDED with `hedged: true` recorded.

**Ledger structure (occurrence-level, per review F6).** Extraction by two subagents (one per raw dir), each emitting one JSONL row per citation OCCURRENCE with verbatim source quote + file path + per-occurrence attributed claim. I link occurrences to canonical-work records (key: DOI/arXiv ID when available, else first author + normalized title + year with ±1 tolerance; titleless candidates key on first author + venue + year) into `p3-provenance/ledger.jsonl` (occurrences) + `works.jsonl` (canonical works). Extraction recall audit (pre-specified, review F5): after extraction, I personally fully re-read 2 files per dir chosen by seeded RNG (seed 20260719) and count missed qualifying occurrences; reported as a recall bound on the denominator.

**Verification protocol (per canonical work, with per-occurrence claim checks; grades decomposed per review F7).** Locate the primary via web search / Crossref / arXiv / PubMed; fetch the abstract page (bare `safefetch` only in subagents; WebFetch forbidden). Stop rule: up to 3 search queries + 2 page fetches per work, then the Wayback fallback (novelty-protocol §8), then UNVERIFIABLE. Three separate facets per work: `exists` (yes / no / unverifiable); `biblio` (full match / minor deviation = year ±1 or journal-vs-proceedings variant or subtitle truncation / major mismatch = wrong venue, wrong authors, year off >1); and per-occurrence `claim_support` (supported at abstract-or-title level / not locatable there / contradicted). Scope limit (explicit): P3 verifies citations — existence, bibliography, attributed content — NOT whether the work truly "owns" the concept; ownership adjudication is the novelty-position programme's job, out of scope here. Kill-verification rule: every `exists=no`, `biblio=major`, or `claim=contradicted` verdict re-checked by me against the primary personally; 5 verified works sampled for re-check by seeded RNG (seed 20260719); subagent grading is a measurement instrument and is itself audited — stated limit.

**Pre-registered endpoints.** 1) PRIMARY: occurrence-level survival rate = occurrences whose work has `exists=yes` AND `biblio` ∈ {full, minor} AND that occurrence's `claim_support=supported` / total occurrences. 2) Unique-work validity rate (same rule at work level, any-occurrence-supported) — secondary. 3) Failure taxonomy counts on both levels. Exploratory (labeled): survival by hedged vs confident; by source experiment (naming vs backtest); cost per verified work (fetches + wall-clock).

## P4 — union-of-keys recall (only if time remains)

**Question.** The §4-revision retrieval claim: does a union of keys (raw term + question + definition) beat any single key? One exploratory run on the frozen 18-doc corpus.

**Inputs.** Frozen rankings from `eval/e2e-cell/runs/retrieval.json` (K1, K2, N, D-sonnet, D-opus) + E = the raw excerpt-pool key (method of `probe_extractive_key.json`), recomputed to a FULL 18-doc ranking with the same model + serialization. The probe's ad-hoc script was not persisted, so the E query text is reconstructed: two variants (full `c2-excerpts.md` file; bodies-only with headers and source lines stripped) are tried in that fixed order and the first whose top-5 equals the archived probe top-5 is frozen as E, with the matching variant logged in the output (implemented in `p4-union-keys/fuse_p4.py`). Sanity gate: if neither variant reproduces the archived top-5, P4 stops and reports the mismatch.

**Fusion rule (pre-registered before any fusion is computed).** Reciprocal rank fusion, score(d) = Σ_keys 1/(60 + rank_k(d)), ties by doc id ascending. Fusions: U3s = {K1, N, D-sonnet}; U3o = {K1, N, D-opus}; U5 = {K1, K2, N, D-sonnet, D-opus}; U6 = U5 + E.
**Comparison rule (pre-registered, symbolic per review F8).** For each fusion F with constituent set C(F): best constituent B(F) = argmin over k∈C(F) of first-owner rank, ties broken by higher hits@5. Weak dominance: rank(F) ≤ rank(B(F)) AND hits5(F) ≥ hits5(B(F)). "Union-beats-single" is SUPPORTED on this cell iff BOTH U3s and U3o weakly dominate their B(F), AND at least one of the four (fusion ∈ {U3s, U3o}) × (metric ∈ {first-owner rank, hits@5}) comparisons is strictly better. Otherwise NOT SUPPORTED (reported either way). U5/U6 are exploratory context, as is false-positive load = non-owner docs in top-5, split misroute vs distractor.

**Caveats (stated up front).** Post-hoc corpus (assembled answer-aware for the e2e cell); D keys are fidelity-FAILED, so any union containing them routes a drifted construct — this measures key MECHANICS, not construct fidelity; exploratory demo, promoted no further regardless of outcome.
