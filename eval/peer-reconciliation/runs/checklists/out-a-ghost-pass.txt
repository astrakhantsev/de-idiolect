- Mechanism: a test/eval run reads results from a cache keyed on task hash instead of re-executing the task, so cached/stale trace data silently stands in for real execution.
- What's measured/produced: pass/fail status and scores for tasks in an audit run, which get reported as if freshly generated by re-execution.
- Trigger/setting: occurs when a cache is not busted before rerunning a suite (e.g., after a wrapper/code fix), so stale entries persist across runs.
- Scoring corruption: the agent/model is credited for task outcomes it did not actually produce during that run.
- Trend-integrity constraint: once contamination is found, prior "clean" audit cycles become untrustworthy since it's unknown how many were partially cached.
- Detection method: forcing a cache bust and re-running is what reveals the discrepancy (previously passing tasks failing outright).
- Comparative-validity constraint: reported wins/improvements over a baseline can themselves be invalid if the run underlying the comparison was contaminated.
