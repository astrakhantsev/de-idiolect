## Materials and ground truth

- `key/concepts.json` — 18 fictitious agent-evaluation concepts with per-side description slices and orchestrator-assigned coined terms (10 terms per side). `key/answer_key.json` — the 10 evaluation pairs with expected outcomes. Both files are OUTSIDE every pipeline call's reachable filesystem (calls run via `../e2e-cell/run_isolated.sh`: fresh cwd + credentials-only HOME; the prompt file is the only input).
- Planted classes (all six outcomes): 2 exactMatch · 1 broad/narrow with A broader · 1 broad/narrow with B broader · 2 relatedMatch (shared core + planted per-side residues) · 2 jingle (identical orchestrator-assigned term string, different concepts → noMatchDespiteSimilarity) · 2 noMatch distractors.
- Corpora: community A ("practitioner forum" register) and B ("preprint/methods" register), 11 docs each, 150–300 words, generated by DIFFERENT model families (A: claude sonnet; B: codex gpt-5.6-terra). Generators receive ONLY their side's term assignments + concept slices + register/usage rules — never the other side's terms, never relation labels, never the pair list. Generators are instructed to write applied/incidental usage (worked examples, disagreements, measurements) and NO definitional prose.

## Leak checks (frozen; `leakcheck_peer.sh`)

(i) No coined term of one community appears in the other community's corpus — EXCEPT the two whitelisted jingle strings ("drift audit", "ghost pass"), which legitimately appear in both. (ii) No key-file meta-vocabulary in any generated doc or definition: exactMatch, broadMatch, narrowMatch, relatedMatch, noMatch, "broader", "narrower", "shared core", "residue", "planted", "answer key", "relation", "community A", "community B", "jingle". (iii) No coined term string (either side's) inside any generated definition. Any hit → regenerate the offending artifact (regeneration, never hand-patching — the 07-16 deviation is not repeated); regeneration attempts logged.

## Excerpt extraction (mechanical, no model in the loop)

Sentence split on `[.?!]` + space + capital. An excerpt = the sentence containing the term string (case-insensitive) plus the following sentence when the match sentence has <12 words. DEV = docs 01–08 per side; HELD-OUT = docs 09–11 (reserved for the deferred E2). Verification sample per term: first **n = 6** DEV excerpts in (doc, position) order; if <4 DEV excerpts exist, pull from HELD-OUT in order and LOG the encroachment (flags that pair for E2); if still <4 → the pair is ABSTAIN (input-insufficient), scored insufficientEvidence.

## Definitions

Per term, per side: constrained term-free operational definition generated from that term's DEV excerpt bundle ONLY (isolated call; D_A by claude opus, D_B by codex gpt-5.6-terra — the two sides' definitions come from different families, entry property 1). Leakcheck (iii) + (ii) on every definition. **Polarity-only gate** (explicitly NOT the e2e multi-dimension fidelity gate, per review F14): one batched call per side (D_A judged by codex, D_B judged by opus) asking, per definition: does it invert or reverse the direction/polarity of what the excerpts describe? verdict per definition `ok | inverted`; `inverted` → that side of every affected pair is **configFail** (a result, not a retry).

## Verification (the F1 fix, frozen)

Per pair (term_a, term_b), two directions: D_A against E_B(term_b) and D_B against E_A(term_a). Per excerpt `e`, tested proposition: **"the referent of the partner term as used in `e` is an instance of the concept defined by the definition."** Verdict `instantiates | contradicts | insufficient`; `instantiates` and `contradicts` REQUIRE a verbatim quote from `e` (quote grep-checked against the excerpt; missing/failed quote → verdict downgraded to `insufficient` at scoring time). One batched call per pair-direction (all 6 excerpts, JSON out). Judge families: D_A-vs-E_B → claude opus; D_B-vs-E_A → codex gpt-5.6-terra (each side's excerpts judged by the family that did NOT write them).

Aggregation per direction (k = #instantiates, c = #contradicts, u = #insufficient, n = excerpts sampled): `u > n/3` → **abstain**; else `covers` iff k/(n−u) ≥ 0.7 AND c = 0; `fails` iff k/(n−u) ≤ 0.3 OR c ≥ 2; else **mixed**.

## Composition → proposed_relation (frozen rule order; the F2 fix)

1. Either side polarity configFail → **configFail**. Either direction abstain → **insufficientEvidence**.
2. covers ∧ covers → **exactMatch**.
3. covers(D_X on partner excerpts) ∧ fails(D_Y on X's excerpts) with c ≥ 2 on that failing direction (the cited counterexamples, review F2's breadth requirement) → **broad/narrow with broader_side = X**. SKOS triple derived deterministically: (narrower side's term, skos:broadMatch, broader side's term); subject = narrower (review F9).
4. covers ∧ mixed, or fails-without-counterexamples asymmetries → **insufficientEvidence**.
5. fails/mixed ∧ fails/mixed → if mutual retrieval hit AND decompose succeeds → **relatedMatch**; else if surface-similarity flag → **noMatchDespiteSimilarity** (rejection evidence = the contradicts quotes); else → **noMatch**.

- **Mutual retrieval hit**: bge-large-en-v1.5 (e2e retrieve.py pipeline), query = each definition against the OTHER side's 11-doc corpus; hit iff ≥1 of top-3 docs contains the partner term string; mutual = both directions hit.
- **Surface-similarity flag**: identical normalized term strings, OR character-trigram Jaccard ≥ 0.5 between the two term strings.
- **Decompose success** (minimal, sonnet, one call per candidate): given BOTH sides' DEV excerpt bundles (never the definitions — the verification stage stays definition-vs-usage only), produce a shared-core statement + ≥1 verbatim quote from EACH side (grep-verified) or the literal token ABSTAIN. Success = core + both quotes verified + no ABSTAIN.

Fields: proposed_relation, adjudicated_relation (stamped `synthetic-key-<sha8>` at scoring), status ∈ {proposed, adjudicated, rejected, abstained}, per-direction verdict arrays with quotes, broader_side?, evidence provenance (model families + prompt sha256s), derived_from [], earliest_found_in_search {synthetic, labeled} with the fixed note "no priority inference licensed". ## What this can and cannot establish

CAN: pipeline runs end-to-end; frozen aggregation discriminates planted classes ≫ chance on cooperative data; jingle verdict reachable; record/ID/fork machinery delivers coexistence; degenerate always-match / always-no-match verifiers excluded by the class-balanced key. CANNOT: anything about wild pairs, discovery lift, the no-canonical regime, definition neutrality, or transfer (7/7 recipes-die-on-transfer prior). Named circularities: judged excerpts share a family with one side's definition generator (mitigated only across, not within, sides); synthetic docs risk paraphrasing the key (mitigated by the no-definitional-prose rule; E1 difficulty is a lower bound on wild difficulty); cross-family generation mitigates but does not eliminate style-bridging (Guard-0 cross-cosine between corpora reported as a difficulty diagnostic, not gated).

## AMENDMENT v0.3 (logged 2026-07-19, BEFORE any v0.3 call; v0.2 results stand as recorded)

Motivated by the v0.2 E1 failure diagnosis (one-sided: all misses were abstentions; zero wrong relations). Two changes, everything else unchanged:

1. **Aggregation rule (replaces u > n/3):** let decidable = k + c. Abstain iff decidable < 2. Else `covers` iff k ≥ 2 AND c = 0; `fails` iff c ≥ 2 OR k/(k+c) ≤ 0.3; else `mixed`. Rationale: per-excerpt insufficiency is the expected state on incidental usage; it must not be read as bundle-level evidential absence.
2. **Excerpt window (replaces match-sentence + conditional next):** preceding sentence + match sentence + following sentence, clipped at doc bounds; the <12-word conditional is dropped.

Held fixed to isolate the two changes: corpora, definitions (v0.2 outputs reused verbatim), polarity verdicts, retrieval (definitions unchanged ⇒ retrieval.json unchanged), all prompts, models, composition rule order, endpoints. Consequence accepted in advance: P05's relatedMatch path remains closed by mutual-hit = false (frozen retrieval leg) — P05 is expected to score wrong; the achievable ceiling is 9/10 against the unchanged ≥7 bar.

**E2 (now run, completing the deferred endpoint), frozen before running:** for each of P05 and P06: (a) a full decomposition call (sonnet, new prompt decompose-full.md) must produce {core, residue_a, residue_b} each with a verbatim quote from its side's DEV excerpts (masked-text validation), no ABSTAIN; (b) core-check: the core judged (verify-pair template; A-side held-out judged by codex, B-side by opus) against each side's HELD-OUT excerpts — PASS iff ≥1 instantiates and 0 contradicts per side (weaker than the v0.3 rule because held-out n is 1–4; stated as such); (c) residue far-side exclusion: each residue text embedded (bge) against the 6 held-out docs (3 own-side + 3 far-side); a residue passes iff the top-ranked doc is own-side; the pair needs ≥1 of its 2 residues passing. **E2 PASS = both pairs satisfy (a) ∧ (b) ∧ (c).** Known contamination flag carried from v0.2: P06 side-A has a single held-out excerpt and it was consumed by the encroachment rule during verification sampling — P06's core-check is flagged accordingly in reporting.

## AMENDMENT v0.4 (logged 2026-07-19, BEFORE any v0.4 call; v0.2/v0.3 results stand as recorded)

Motivated by the v0.3 diagnosis (failure at the representation layer: window contamination, definition abstraction-level defects, genus-level decompose cores). Three changes:

1. **Excerpt hygiene:** window sentences (prev/next) that contain a DIFFERENT same-side coined term are DROPPED from the window (the match sentence is always kept); in all prompt classes, every other same-side coined term occurring in excerpt text is masked as ⟦X⟧ (target term masked ⟦TERM⟧/⟦T1⟧/⟦T2⟧ as before). Quote validation checks against the fully-masked text the judge saw.
2. **Checklist-guided definitions (the P2 recipe):** per term, one isolated sonnet call extracts a 4–7 item commitments checklist from the term's masked DEV bundle (must include the specific mechanism; no generalization beyond the excerpts); definitions are regenerated (same families: D_A opus, D_B codex terra) under a new template requiring every commitment to be stated and banning catch-all generalization phrases ("or otherwise", "or any similar", "in any way"). Checklists are leak-checked like definitions.
3. **Core specificity gate:** decompose success (both the composition gate and E2's decompose-full) additionally requires: embed the core (bge); rank all 20 per-term masked DEV-bundle embeddings by cosine; BOTH of the pair's own bundles must be in the top 3. Computed offline (`core_specificity.py`), written to `runs/core_specificity.json`; missing entry = fail.

Re-run scope: excerpts, checklists (new), definitions, polarity, retrieval, verification, decompose, E2 chain. Held fixed: corpora, aggregation rule (v0.3), composition rule order, endpoints and bars, models and family assignments, records machinery. v0.3 artifacts archived to runs/v03-archive/. Known carry-overs accepted: P05-b core-check may hit the deterministic classifier refusal again (unscoreable handling stands); P06-a single held-out excerpt remains encroachment-flagged.
