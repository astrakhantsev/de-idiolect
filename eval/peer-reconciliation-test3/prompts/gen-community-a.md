THE COMMUNITY'S TERMS (its own coinages — use them exactly as given, no synonyms, no abbreviations, no other names for these ideas):

1. "pivot check" — Partway through execution a scripted user message reverses an earlier instruction; graders record whether the agent discards the now-invalid partial work and pursues the revised objective, versus finishing the stale one. Scored as the fraction of trials in which the agent fully switches without carrying abandoned artifacts into its final output. Applies to multi-turn interactive runs where instructions can change mid-task.
2. "garble replay" — A recorded run is executed again while every tool result is replaced with syntactically valid but semantically meaningless content. Observers track whether the agent flags the unusable feedback and requests a retry rather than proceeding as though the output were sound. Reported as the proportion of degraded steps that trigger an explicit recovery attempt. Used when assessing how a testing rig behaves under faulty observation channels.
3. "quit sense" — Any assessment of whether an agent halts at the appropriate moment rather than continuing needlessly, regardless of how the stopping condition is detected. It spans premature abandonment, unbounded looping, and pushing on past a finished objective, and is evaluated by comparing the actual stop point against an ideal stop point for the task. Every specific stopping-behavior probe sits inside this general question.
4. "example strip" — A single specific case within the wider study of how much supportive instruction structure props up performance: the solved demonstrations are deleted from the prompt while formatting cues, step outlines, and hints are left untouched, and the resulting success drop is recorded. It probes the demonstrations alone, one element among the several supportive ingredients the wider study also weakens.
5. "brain swap" — A task is repeated with the component that produces the high-level plan reassigned to a cheaper model while every execution step retains the original model. The change in overall task success between the two runs is recorded to reveal how much the planning component was carrying the result.
6. "double mark" — One agent answer is submitted to the automated scorer twice, with the answer's whitespace and line wrapping reflowed between the two passes while its content stays byte-equivalent in meaning. Disagreement between the two verdicts is logged across a corpus of answers.
7. "cold start" — The very first task an agent attempts in a fresh session is scored apart from all later tasks in that session, capturing how much weaker it performs before settling into a working rhythm with the tools on offer. The gap between the opening task's score and the session-wide average is reported as the ramp-up penalty.
8. "hot swap" — Partway through an unfinished task the underlying model is exchanged for a different one without clearing accumulated run state. Observers judge whether the successor continues coherently from the existing context — honoring decisions already made and files already edited — rather than restarting from scratch or contradicting the earlier steps it inherited.
9. "spray test" — One identical task is dispatched to a large batch of worker instances executing simultaneously against shared infrastructure. Results are inspected for cross-contamination — instances reading each other's scratch files, clobbering a common cache, or racing on a shared port — and the contamination rate is reported as a concurrency-safety figure for the execution fabric.
10. "budget bleed" — Across a run, the token cost consumed by attempts that were later discarded, undone, or retried is accumulated separately from cost that fed into the delivered result. The ratio of dead-end expenditure to total expenditure is reported; high values flag an agent that thrashes among approaches instead of converging.
