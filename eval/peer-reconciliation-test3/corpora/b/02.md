# Mid-Run Reversal Trials

Interactive maintenance tasks were interrupted after an agent had created an initial patch, inspected a relevant module, or begun a test run. The scripted follow-up either redirected the target component or withdrew the requested change entirely. Goal-revision compliance rate was measured over 360 interrupted trajectories. Goal-revision compliance rate reached 0.79 for the instruction-tuned system and 0.54 for the base system, with stale diffs accounting for most unsuccessful switches.

An objective checker was run after every executable action and marked the earliest point at which the revised task was fully satisfied. Post-completion action count averaged 2.8 for trajectories that had correctly switched objectives. Post-completion action count was higher, at 6.1, when an agent retained obsolete notes or continued testing the superseded component. The excess was largely attributable to repeated repository searches rather than destructive edits.

The reversal message was delivered at only three predetermined progress bands, which limits conclusions about more adversarial timing. In particular, the protocol did not test reversals received while a long-running command was active. Nevertheless, the results show that final-answer correctness alone concealed substantial variation in abandoning earlier work.
