# Revisions Under Variable Provisioning

The interactive suite injected instruction reversals after a repository had loaded but before the agent’s first code modification. Cold start was recorded independently for every trial and removed from the response-time analysis. Cold start varied from 18 to 96 s across worker pools, with no detectable association with whether the agent ultimately changed objectives. This separation avoided attributing queueing delays to slow reconsideration.

Goal-revision compliance rate was analyzed after stratifying trials by the number of actions already taken at interruption. Goal-revision compliance rate declined from 0.82 in early interruptions to 0.61 after an initial patch had been written. Agents that failed commonly retained a correct implementation of the original request and appended an incomplete revision.

Component substitution elasticity was measured by replacing only the tool-selection module during the same interrupted runs. Component substitution elasticity was positive for the replacement selector, which consumed 4.3 additional actions on average after a reversal. The added actions were primarily repository searches used to re-establish context.

The design did not vary the wording or politeness of the revised instruction. As a result, the reported effect applies to explicit reversals and may not generalize to subtler changes in user intent.
