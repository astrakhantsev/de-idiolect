# Cheap planner, same executor, same score?

Ran a brain swap on our document-QA agent, keeping the exact same execution model but routing the planning step through a much cheaper backend. Expected a cliff and didn't get one — score held at 81% versus 83% baseline, basically noise. Either our planning step for this particular task is trivial enough that a cheap model handles it fine, or the executor is quietly redoing planning work on its own regardless of what the plan handed it. Going to test that second theory by literally blanking the plan output and seeing if execution still holds up.

Cold start on this same agent is the more interesting problem honestly. First task of a session averages 15 points under the session mean, and it doesn't seem tied to task difficulty, we controlled for that. Feels like the agent needs one or two tool calls just to remember which of our retrieval indexes is authoritative versus deprecated, and nothing in the system prompt currently front-loads that. Going to try seeding session memory with that fact and rerun cold start to see if the gap closes.

Last thing, we double marked a batch of these QA answers after noticing the scorer seemed inconsistent on long-form responses. Reflowed line breaks, changed nothing else, resubmitted through the same grader. 9 out of 80 flipped verdicts. That's a bigger disagreement rate than I want to admit to our stakeholders, so we're auditing the grader's whitespace handling before we trust any of these session-level comparisons further.
