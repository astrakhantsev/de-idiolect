# Mid-task reversals are still eating our scores

Ran another batch of pivot check trials this week and the number is stuck around 61%, barely moved since last quarter. The failure mode is so consistent it's almost funny: user says "actually forget the CSV export, give me a JSON summary instead" at turn 4, and the agent dutifully starts the JSON work but still tacks the half-finished CSV onto the final answer like a scar tissue artifact. We've started diffing the final output against the abandoned branch just to catch it automatically instead of eyeballing transcripts.

Separately, I ran a garble replay pass on the same session logs to see if the two failure modes correlate, and they mostly don't. Garble replay is a different beast entirely — you feed the agent noise where the tool output should be, syntactically fine JSON with meaningless fields, and watch whether it just barrels forward treating garbage as gospel. Our agent actually does okay here, flags the malformed-looking data and asks for a re-fetch about 80% of the time. So it's weirdly better at detecting bad inputs than at abandoning bad outputs.

The quit sense angle ties both together for me now. It's not that the agent doesn't know how to stop — the garble replay numbers prove it can recognize when something's wrong and halt to ask. It's specifically that once it's invested tokens into a plan, sunk cost takes over and it can't let the CSV branch die even after being told explicitly to. Anyone else seeing this split between "notices bad input" and "can't drop bad output"?
