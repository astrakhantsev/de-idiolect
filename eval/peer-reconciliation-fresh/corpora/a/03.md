# Nondeterminism, metadata leakage, and a diary entry that actually paid off

Did an echo test on the new retrieval agent before we shipped it — same exact prompt, same session, submitted twice. Temperature's pinned to zero on paper, but outputs diverged by about 6% token-for-token, and once by a full different citation. That's not the model, that's the serving stack doing something nondeterministic downstream, probably batching-related, and it means our confidence numbers this month have that much slop baked in regardless of the actual reasoning quality.

Ran a salt run right after to sanity-check the scorer while we were at it. Randomized every timestamp, run id, and output filename we could find and reran the same 80 tasks. Score moved by three points. Should've moved by zero. Something in the harness is keying off metadata it has no business looking at, and now I have to go find it before the echo test numbers mean anything.

Good news is the rig diary actually saved us here. Scrolled back through it and found an entry from eleven days ago noting we'd swapped the artifact-naming scheme in the scorer's config to include run id in the cache key. That's almost certainly the leak. Nobody would've remembered that without the log — it wasn't in any PR description, just a one-line diary note.
