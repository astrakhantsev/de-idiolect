# Parameters — the decisions embodied in the de-idiolect workflow

> **Post-submission addition (2026-07-24), a ledger of the tool's parameters — no new claims, no grade changes.** The as-submitted state is tagged `flf-submission`; ENTRY.md is unchanged. This page names each design decision (parameter) the workflow embodies, its value at submission, how it was chosen, and how a re-user on their own data would choose it. It carries the entry's **at-submission** grades wherever a component's status is mentioned (e.g. detection is not wired into the measured path; the composed pipelines are `[U]`; the inward hook was "argued and unbuilt" at submission). It introduces no new result; on any exact value, the frozen pre-registration is authoritative — [`eval/peer-reconciliation-fresh/prereg-v08.md`](eval/peer-reconciliation-fresh/prereg-v08.md) (mechanical validators + gate state machine; sealed-test twin at [`eval/peer-reconciliation-test3/prereg-v08.md`](eval/peer-reconciliation-test3/prereg-v08.md)) and [`prereg-v09.md`](eval/peer-reconciliation-fresh/prereg-v09.md) (the operating-point schedule) — linked rather than duplicated below.

## The ontology this page exists to protect

A **parameter** is a decision the *tool* embodies (the L2 word cap, the regeneration budget, the embedding model). An **evaluation protocol** then *freezes* a particular value of a parameter so a sealed test is well-defined. "Frozen in the protocol" is therefore a **custody status** — where a value currently sits — not the nature of the thing. The same L2 word cap is a tunable tool knob *and* a frozen protocol constant *and*, in a drafted revision, a proposed change; the value has a lifecycle, and the page tracks it.

Distinct from parameters are **protocol-level constants** — the ≥7/10 bar, n=10 planted pairs, sealed-key custody, report-regardless. These define the *evaluation*, not the tool; a re-user running the workflow on their own data inherits none of them. They are listed separately in §6 precisely so they are not read as tool knobs. Conflating the two is the confusion this page prevents.

**Custody status** (every parameter carries exactly one):

- **free knob** — a re-user sets it for their own data; nothing in the evaluation fixes it.
- **frozen in the sealed protocol** — pinned by the v0.8 pre-registration (carried verbatim into the v0.9 run the sealed test was scored under); changing it changes the test.
- **changed post-submission** — introduced or altered after the 2026-07-19 deadline, labeled and dated.
- **under drafted v0.10 revision** — a value a pre-registration *draft* proposes changing; **not frozen, not run, not decided** — a paper proposal pending sign-off.

Fields per parameter: *what it controls · value at submission · how chosen (measured / arithmetic / judgment / inherited) · how a re-user chooses · custody.*

## 1. Artifact-format parameters — the vocabulary-seam ladder and checklist

The tool's output for one term is a three-rung cumulative **ladder** (L0/L1/L2) plus a **commitments checklist**; the format is enforced by the mechanical validators in [prereg-v08.md §9-F5](eval/peer-reconciliation-fresh/prereg-v08.md). Exact validator text is there; the decisions are below.

**Why a length cap exists at all** (applies to every length parameter here): (i) *leak surface* — a longer artifact leaves more room for the community's own identifying vocabulary to reappear, defeating the term-free premise; (ii) *anti-padding* — unbounded length degenerates toward pasting the excerpt back, which converges on the equal-information direct ask the tool is trying to beat (that comparator is [BASELINES.md](BASELINES.md)'s Baseline B, against which the pipeline's mechanical form earned no measured margin); (iii) *format identity* — a stable band keeps the artifact the same shape across versions so results compare.

- **L0 length** — the genus rung. Controls: the one-sentence "what kind of thing it is." Value: exactly 1 sentence AND ≤ 45 words. Chosen: judgment (genus-only, no mechanism) plus an arithmetic cap. Re-user: keep ~1 sentence; the 45 is a sanity ceiling, loosen only if your genus statements are legitimately long. **Custody: frozen in the sealed protocol.**
- **L1 length** — the mechanism rung. Controls: L0 plus the specific mechanism/process. Value: 2–4 sentences. Chosen: judgment (enough to state a mechanism, not a full spec). Re-user: free to widen. **Custody: frozen in the sealed protocol.**
- **L2 word band** — the richest rung. Controls: L1 plus what is measured/produced and when it applies. Value: **60–160 words** (both a floor and a ceiling). Chosen: inherited then hardened (see the lifecycle box). Re-user: raise the ceiling for commitment-rich concepts; keep a floor to force operational content. **Custody: frozen in the sealed protocol** (a drafted v0.10 revision proposes keeping 160 with an evidence-gated escape hatch — below).
- **Monotone word counts** — Controls: that each rung is strictly longer than the last. Value: w(L0) < w(L1) < w(L2). Chosen: arithmetic proxy for "each level genuinely adds." Re-user: keep; it is nearly free. **Custody: frozen in the sealed protocol.**
- **Cumulative-ladder requirement** — Controls: that each rung *contains* the one below (L2 ⊇ L1 ⊇ L0), checked by a semantic conformance judge (L1 preserves L0's content and states the checklist mechanism; L2 preserves L1 and states every checklist commitment). Value: enforced. Chosen: judgment (a ladder that drops a lower level's commitment at the next level is not a ladder). Re-user: keep if you use the ladder shape at all. **Custody: frozen in the sealed protocol** (a drafted v0.10 revision proposes *cumulative-extension generation* — generating so L1 literally opens with L0's text plus mechanism, L2 with L1's text plus measurement — to remove the violation by construction; **under drafted v0.10 revision, not frozen, not run**).
- **Checklist size** — Controls: the number and length of extracted commitments a faithful definition must state. Value: 4–7 non-empty lines, each ≤ 40 words. Chosen: judgment (enough coverage without padding). Re-user: widen for richer concepts. **Custody: frozen in the sealed protocol.**

> **Worked example — the lifecycle of one value (the 160 cap).** The 60–160 word band did not start as a protocol constant. It first appears as a *generation-prompt* length band in [`gen-definition-v04.md`](eval/peer-reconciliation-fresh/prompts/gen-definition-v04.md) (the earlier [`gen-definition.md`](eval/peer-reconciliation-fresh/prompts/gen-definition.md) used 60–140), i.e. a soft instruction to the generator. It carried forward into [`gen-definition-v07.md`](eval/peer-reconciliation-fresh/prompts/gen-definition-v07.md), the frozen generation prompt. It was then *hardened* into a **mechanical validator gate** in [prereg-v08.md §9-F5](eval/peer-reconciliation-fresh/prereg-v08.md) — a hard pass/fail the sealed v0.9 run was scored under. A drafted v0.10 pre-registration proposes **keeping 160 with a TRAIN-evidence-gated escape hatch** (raise it only against the cumulative ladder's own arithmetic, and only after a fresh-TRAIN validation gate is met) — **a draft, not frozen, not run.** One value; four custody states across its life. That is the whole point of separating "what the value is" from "who currently holds it."

## 2. Gate / state-machine parameters

Every generated artifact runs a fixed gate sequence with a total regeneration budget; the state machine is [prereg-v08.md §1](eval/peer-reconciliation-fresh/prereg-v08.md) and the per-stage failure table is [§9-F4](eval/peer-reconciliation-fresh/prereg-v08.md).

- **Generator model assignment** — Controls: which model writes each side's artifacts. Value: ladder definitions side a = claude `opus`, side b = codex `gpt-5.6-terra`, one isolated call per term; checklists = for each term on both sides, one isolated claude `sonnet` call ([prereg-v08.md](eval/peer-reconciliation-fresh/prereg-v08.md), pipeline steps 2–3). Provenance nuance, stated exactly: the sealed run's [`freeze-manifest.txt`](eval/peer-reconciliation-test3/freeze-manifest.txt) records a separate freeze-time `modelUsage` probe per alias — observed sets `sonnet` → {`claude-haiku-4-5-20251001`, `claude-sonnet-5`} and `opus` → {`claude-haiku-4-5-20251001`, `claude-opus-4-8`} (the haiku entry appears in both sets and is never any artifact's recorded model) — and this probe does **not** establish provider-side resolution for the later isolated calls: per the prereg's runtime-provenance clause (§9-F9), those per-call manifests record the requested alias and invocation environment only. Chosen: judgment — the cross-family split is an independence control (a shared generator across the seam would manufacture the match), and each side is judged by the family that did not write it (polarity gate, below). Re-user: any two models from different families; probe and record what your aliases actually serve, since provider aliases drift across releases. **Custody: frozen in the sealed protocol.**
- **Regeneration budget** — Controls: how many times a failed artifact is regenerated before the pair terminates. Value: **1 total** per artifact (any gate failure consumes it; a second failure → `configFail` scoped to every pair using that term). Chosen: judgment (one cheap retry, no infinite loop). Re-user: raise if generation is flaky. **Custody: frozen in the sealed protocol** (a drafted v0.10 revision proposes budget **2** for the mechanical and leak classes, semantic budget kept at 1; **under drafted v0.10 revision, not frozen, not run**).
- **Regeneration blindness** — Controls: what the regenerator is told about the failure. Value at submission: **blind** — the frozen protocol re-runs the same generation prompt and does not pass the failing gate's identity or the value it violated. Chosen: inherited (the state machine is the retry policy; no feedback channel was specified). Re-user: worth surfacing the failure to the regenerator if you can. **Custody: frozen in the sealed protocol** (the blind value is what the sealed run ran). This property is worth naming because it is the lever a drafted v0.10 revision targets: **feedback-guided regeneration** (pass the failing gate + measured value + the cap) is proposed as the single biggest change — **under drafted v0.10 revision, not frozen, not run.**
- **Gate order + failure-class routing** — Controls: which gates run, in what order, and where each failure goes. Value: checklist → *generate → leak check*; ladder → *generate → JSON/mechanical conformance → leak check → semantic conformance*. Four failure classes route distinctly — **mechanical**, **leak**, **semantic-conformance** (generation-stage → consume budget → `configFail`), and **quote-validation** (verification-stage → the affected verdict downgrades / pair-scoped `insufficientEvidence`, no retry). Chosen: judgment (cheapest deterministic checks first; infrastructure failures never masquerade as verdicts). Re-user: keep the ordering; it is a correctness property, not a tuning dial. **Custody: frozen in the sealed protocol.**
- **Conformance-judge model call** — Controls: the model that judges cumulativity/checklist-coverage. Value: one isolated **sonnet** call per side, batched ([`prompts/ladder-conformance.md`](eval/peer-reconciliation-fresh/prompts/ladder-conformance.md)); a batch failure → one re-run, then run-halt (it gates everything). Chosen: judgment (a cheap tier suffices for a conformance verdict). Re-user: swap the model freely. **Custody: frozen in the sealed protocol.**
- **Polarity gate** — Controls: catching a definition that inverts the concept's direction/valence. Value: batched per side on **L2 only** (side a judged by codex `gpt-5.6-terra`, side b by opus — each side judged by the family that did not write it); inversion → `configFail` for the affected pairs. Chosen: judgment (a narrow inversion-only check, distinct from completeness). Re-user: keep as a guard; models are swappable. **Custody: frozen in the sealed protocol.**
- **Quote machine-validation folding rules** — Controls: how strictly a required verbatim quote must match the excerpt the judge saw. Value: a quote validates iff it is a contiguous substring after folding **case**, **typographic quotes/dashes to ASCII**, and **collapsing whitespace runs** — with **no word-level alteration** (every word, in order, must appear), so fabricated or edited evidence still fails. Chosen: judgment (strict raw comparison was considered and rejected — it adds false downgrades toward starvation terminals without excluding any fabrication class). Re-user: keep; loosening admits fabrication, tightening starves. **Custody: frozen in the sealed protocol.**

## 3. Matching / scoring parameters

The sealed harness scores matches at pre-registered operating points with a fixed relation vocabulary. Exact aggregation and composition are in [prereg-v08.md §§2,5,6](eval/peer-reconciliation-fresh/prereg-v08.md); the operating-point schedule is in [prereg-v09.md §0.2](eval/peer-reconciliation-fresh/prereg-v09.md).

- **τ operating points** — Controls: how much verification evidence a level needs to count as "covered," which sets recall/coverage. Value: a frozen schedule **{τ0, τ1, τ2}** with **τ1 the primary** (τ0 = v0.8 verbatim, covers iff k≥2 ∧ c=0; τ1 adds evidence-exhausted promotion and an L0+L1 retrieval query; τ2 adds one-dissent-tolerated covers). The sealed run reported 5/10 at *all three*. **Note on custody source:** this is the one ledger value set by the *v0.9* pre-registration, not v0.8 — v0.9 carried v0.8's gates and schemas verbatim and added only this measurement layer. Chosen: measured/judgment (τ1 passed the measured TRAIN basis at 7/10 while keeping v0.8's zero-contradiction posture; τ2's only gain accepts a valid dissent). Re-user: a *live* user's operating τ is a **free knob** — a user-level setting that routes verdicts to a review queue and never alters frozen scoring ([`review_pairs.py`](eval/peer-reconciliation-fresh/review_pairs.py)). **Custody of the sealed schedule: frozen in the sealed protocol.**
- **Precision definition** — Controls: how a "false match" is counted. Value: **detection precision** = asserted matches that are true matches ÷ all asserted matches, where a positive is any hard match-class verdict or `reviewRequired` ([prereg-v08.md §6 E1b](eval/peer-reconciliation-fresh/prereg-v08.md)); **typing precision** = exact relation on asserted pairs ([`pr-curve.svg`](eval/peer-reconciliation-fresh/pr-curve.svg)). The sealed run held detection precision 1.00 at every point. Chosen: judgment (a conservative tool must never assert a false match). Re-user: this is the definition you report *against*, not a tuning dial. **Custody: frozen in the sealed protocol** (a scoring definition).
- **Relation-type enums** — Controls: the vocabulary of verdicts. Value: hard relations `exactMatch · broadnarrow(broader_side) · relatedMatch · noMatch · noMatchDespiteSimilarity`, the escalation `reviewRequired(reason)` (never a promotion), and terminals `insufficientEvidence · configFail` ([prereg-v08.md §3](eval/peer-reconciliation-fresh/prereg-v08.md)). The outward prototype uses SKOS names verbatim (`skos:exactMatch/broadMatch/narrowMatch/relatedMatch`) — local names for standard relations would repeat the error being fixed. Chosen: judgment (first-class abstention + "no match despite surface similarity"; explicit broad/narrow direction). Re-user: keep the enums; the closed set is load-bearing. **Custody: frozen in the sealed protocol** (relation typing was measured only in the §5.5 synthetic harness — `[M synthetic]`; the §5.1 prototype ships it as an interface, not a live measured run).
- **Containment schema** — Controls: the structured output of the containment check that resolves broad/narrow direction. Value: `{"relation" ∈ {t1_within_t2 | t2_within_t1 | partial_overlap | no_relation | unclear}, "quote_1", "quote_2", "justification"}`, all four keys present as strings; quotes required and machine-validated for every decided relation, `unclear` quote-exempt ([prereg-v08.md §§2.10, 9-F5](eval/peer-reconciliation-fresh/prereg-v08.md)). Chosen: judgment (neutral framing, an explicit `no_relation` outcome, evidence-required decisions). Re-user: keep the schema; the quote requirement is the anti-fabrication guard. **Custody: frozen in the sealed protocol.**
- **Retrieval hit rule** — Controls: when one side's definition "finds" the other's term. Value, exactly: the query is each side's **full L2 text** at τ0 (the v0.8 rule, verbatim), and the concatenation **L0 + " " + L1** (single space, that order) at τ1/τ2 (set by v0.9), run against the *other* side's full 11-doc corpus; **hit iff the partner term string appears as a case-insensitive substring in ≥1 of the top-3 documents; mutual = both directions hit**; ranking by descending cosine, ties broken by lower document index ([prereg-v08.md §2.6](eval/peer-reconciliation-fresh/prereg-v08.md); [prereg-v09.md §0.2](eval/peer-reconciliation-fresh/prereg-v09.md)). Chosen: judgment (top-3 mutual is a conservative bidirectional gate; the L0+L1 query was adopted at v0.9 on measured TRAIN evidence). Re-user: widen top-k for recall, tighten for precision. **Custody: frozen in the sealed protocol.**

## 4. Outward prototype parameters (`prototype/`)

The runnable §5.1 prototype ([`prototype/README.md`](prototype/README.md)); its retrieval stage is the load-bearing measurement, offline and deterministic. Detection here is **not wired into the measured path** (the evaluated concepts are hand-supplied) — the at-submission grade the page preserves.

- **Embedding model** — Controls: the retrieval encoder for the definition-as-key measurement. Value: **`BAAI/bge-large-en-v1.5`** (~1.3 GB), offline and deterministic once cached; cosine over normalized embeddings. (Also the sealed harness's frozen encoder, §3's retrieval rule.) Chosen: judgment (a strong open encoder that needs no LLM and no network, so the measurement is reproducible). Re-user: swap for any encoder; results are encoder-dependent and no longer comparable to the committed runs. **Custody: scope-split** — in the prototype, a **free knob**; in the sealed harness, the encoder *instance* is **frozen in the sealed protocol** (local snapshot, directory hash recorded in the freeze manifest), so changing it there changes the test.
- **Backend choice** — Controls: whether the generative stages (define, relation-type) run live or from frozen fixtures. Value: `--backend fixtures` (default; deterministic, author-frozen outputs behind the real interface) vs `--backend claude` (live generation; verified routing held). Chosen: judgment (a deterministic committed run plus a live-verified interface). Re-user: `claude` to generate on your own data. **Custody: free knob.**
- **`--define-only` mode** — Controls: whether owner-rank scoring runs. Value: off by default; on → definitions + retrieval rankings with **no answer key** (a demonstration, not a measurement; the output switches to a ranked-top-k view and drops `owner_best_rank`/`routing_gain`). Chosen: judgment (let a re-user with no ground truth still exercise the interface). Re-user: use it whenever you cannot assert an owning community. **Custody: changed post-submission** (2026-07-23 CLI addition; the default eggs invocation is byte-identical to before).
- **Corpus / concepts schemas** — Controls: the shape of a re-user's own data. Value: `documents` need `id` (unique), `community`, `text`; `concepts` need `term`, `naive_question`, plus `owning_community` (+ `constrained_definition` or a live call) for the **scored** path, or neither for the **unscored** path ([`templates/corpus-template.json`](prototype/templates/corpus-template.json), [`templates/concepts-template.json`](prototype/templates/concepts-template.json)). Chosen: judgment (minimal fields; loud failure on malformed input). Re-user: this *is* the knob for your material — real passages, no fabrication. **Custody: split by age** — the schema itself is as-submitted (the shipped eggs files use it); accepting *user-supplied* files (`--corpus`/`--concepts`), the templates, and the unscored path are **changed post-submission (2026-07-23)**; within that extension, a free knob for your material.
- **top-k reporting** — Controls: how many ranked documents a define-only / custom run prints per query. Value: top-3 per query form. Chosen: judgment (enough to read routing without dumping the corpus). Re-user: adjust for larger corpora. **Custody: changed post-submission (2026-07-23)** — the ranked-top-3 custom view shipped with the own-data path (the as-submitted eggs table reports rank-of-owner instead); tunable within that.

## 5. Inward hook parameters (`hook/`)

The coin-time hook ([`hook/README.md`](hook/README.md)). **At-submission grade preserved:** ENTRY.md §4.2 graded this tool "argued and unbuilt" (`[U]`); the directory is a **post-submission** (2026-07-20) v1 build of exactly that proposal and changes no at-submission grade. Every parameter below therefore carries **changed post-submission** as its base custody, with its own tuning nature noted.

- **Models and draw counts** — Controls: which models answer the reverse-dictionary question, and how many draws per term. Value: **`sonnet,opus`** (2 isolated weights-only draws) for `term-check.sh`; scan phase-2 batch is **sonnet-only**, opus opt-in via `-m`. Chosen: judgment (a small cross-tier read; the README warns two same-family draws are a correlated read, not two opinions). Re-user: set `-m` to any model list. **Custody: changed post-submission** (a free knob within the post-submission tool).
- **Isolation mechanism** — Controls: that the draw cannot see the caller's project vocabulary. Value: fresh temp cwd + a fresh `HOME` containing only the CLI credential file + `CLAUDE_CONFIG_DIR` explicitly pinned to that home + **all tools disallowed**; each draw writes a manifest (prompt hash, home policy, command, output hash). Chosen: judgment, adversarial-review-hardened (an inherited `CLAUDE_CONFIG_DIR` would silently bypass the fresh-HOME boundary — a folded finding). Re-user: do not weaken it; it is the property that makes the draw blind. **Custody: changed post-submission** (a load-bearing invariant, not a tuning dial).
- **Curation gate (scan mode)** — Controls: whether a surfaced candidate can spend a naming draw or enter the seed glossary unreviewed. Value: the default path is gated — phase 1 detects and stops; no naming draw runs until a human marks terms `[x]`; phase 2 additionally drops any term not literally present in the source. **One documented exception:** `--top N` auto-keeps the top N candidates and proceeds without the human mark — an automated bypass of the gate. Chosen: judgment (surfacing is heuristic; an unattended weak candidate would leave a user worse off than no scan mode). Re-user: use the gated path; reach for `--top N` only if you accept unreviewed candidates spending draws and entering the seed. **Custody: changed post-submission** (the gate is the default, not an invariant — the bypass is part of the shipped interface).
- **Glossary-watch trigger** — Controls: when the deterministic Stop hook fires a check. Value: fires on a *new* glossary entry, recognized by a narrow documented regex — `- **term** —` bold lines or `##`/`###` headings, term ≤ 60 chars; first run seeds a baseline and fires on nothing; **≤ 3 terms fire per turn**; `.term-check/off` is the kill switch ([`hook/hooks/glossary-watch.py`](hook/hooks/glossary-watch.py)). Chosen: judgment ("a term entered the glossary, nothing cleverer" — a high-precision trigger by design). Re-user: point `TERM_CHECK_GLOSSARIES` at your files. **Custody: changed post-submission** (a free knob).
- **Excerpt / word budgets** — Controls: how much text each stage sees. Value: `term-check.sh` `--max-words` default **2500** per term; scan detection caps ~**18k** input words (evenly downsampled beyond, recorded in the manifest) and **≤ 10** checked terms per run. Chosen: judgment (bound cost and context). Re-user: raise for longer sources. **Custody: changed post-submission** (a free knob).

## 6. Protocol-level constants that are NOT tool parameters

These define the *sealed evaluation*, not the tool. Changing one changes what "passing" means, not how the workflow behaves — and a re-user running the tool on their own data inherits none of them. They are listed here so they are never read as tunable knobs.

- **The ≥7/10 success bar** — the E1-primary TEST-firing bar: `correct ≥ 7/10` (a `broadnarrow` must match the planted broader_side) ∧ `promotions = 0` ∧ `jingle-specific ≥ 1` ∧ `false escalations ≤ 1` ([prereg-v08.md §6](eval/peer-reconciliation-fresh/prereg-v08.md)). It is a *judgment about what would count as success*, pre-registered before the run — not a setting inside the tool. The sealed run scored 5/10 against it (`[M]`, honest at-submission record; ENTRY §5.5, [EXPERIMENT-LOG E5](EXPERIMENT-LOG.md)).
- **n = 10 planted pairs** — the sealed key's fixed benchmark size (P01–P10). A property of the benchmark, not the workflow.
- **Sealed-key custody** — the key is authored by an isolated model, its concept descriptions never read by the orchestrator; **one TEST run per major version**, only after a TRAIN pass; because per-pair failures were never diagnosed into design changes, the key remains valid for exactly one future major version ([prereg-v09.md](eval/peer-reconciliation-fresh/prereg-v09.md); sealed-test copy under [`eval/peer-reconciliation-test3/`](eval/peer-reconciliation-test3/)). A custody procedure, not a tool setting.
- **Report-regardless** — the pre-commitment to publish the sealed result whatever it is (a miss is reported as a miss, never withheld or quietly retried). A credibility discipline of the protocol, not a parameter.
