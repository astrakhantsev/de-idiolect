# Definition-mediated blind naming — experiment

## 0. What this tests

The proposed pipeline: detect project coinages → auto-generate a detailed operational definition under a controlled vocabulary → use the definition (not the term) as the search key. This experiment tests the **elicitation half** on the project's own history, where the answer key exists: four coined terms from the FLF/judge-dependence programme whose field owners were later found by prior-art sweeps (and, for one, verified against primary text). The measured baseline: searches run in the project's own vocabulary returned confident nulls, 3-for-3 (`novelty-protocol.md` §receipts). The protocol's own lesson — "the knowledge was in the weights the whole time" — predicts that a good definition alone, weights-only, should recover owners. If it does, the definition layer is the cheap automatable step that was missing; if it doesn't, the pipeline needs retrieval, not just representation.

## 1. Design

**Two arms, weights-only (no tools at all), blind (reads blocked), headless `claude -p` from a neutral cwd per novelty-protocol §2 launch shape.**

- **D (definitions arm), 3 draws: opus / sonnet / default.** Input: four anonymized operational definitions (CONCEPT-1..4), generated by the pipeline below. Task: reverse-dictionary question per protocol §3 — what is this called, which fields own it, oldest treatments with citations (≥1 pre-2015 aim), confidence + hedges.
- **K (control arm), 2 draws: opus / sonnet.** Input: the four raw coined terms with only the terse in-project gloss (idiolect preserved). Same question.

**Definition-generation pipeline (the thing under test):**
1. **Excerpt assembly** (context-loaded subagent): verbatim excerpts describing each term, with per-excerpt file provenance, from era-gated sources only — C1/C2 from `flf/` files dated ≤2026-07-12 (before the 07-13 kill); C3/C4 from `judge-dependence/` root+digests+_archive dated ≤2026-07-15 (before the 07-16 sweep). Excluded everywhere: `lit/`, `papers/`, `reviews/`, `ORCHESTRATOR-STATE.md`, anything dated on/after the term's kill date, any passage containing external citations. Verbatim-only + provenance makes steering auditable.
2. **Redaction grep** (orchestrator, mechanical): excerpts scanned against the answer-key term list (authors + canonical terms, list in §4); hits redacted or the excerpt dropped. If a term's excerpts turn out saturated with borrowed field vocabulary (e.g. m* was already framed as n_eff/Kish pre-07-13), that concept's validity is downgraded and noted — the test requires the input to be idiolect, not already-translated.
3. **Definition generation** (tool-less headless model, opus, NO vault context — it sees only the redacted excerpts piped via stdin): 150–250-word standalone operational definition per concept, plain language + simple math, generic application framing (no AI/LLM specifics — does-it-need-LLMs discipline), banned from: project coinages, proper names, citations, field names, guesses at what the concept is called elsewhere.
4. **Output grep** (orchestrator): definitions scanned against the coinage list AND the answer-key list; violations → regenerate with only the offending string disclosed. Definitions then **frozen** (sha256) and pasted in full into §5 of this file.

**Why weights-only:** (a) it isolates the representation question from retrieval; (b) WebSearch consumed the monthly cap once already today; (c) the c1/c2/c3 precedent shows owners are reachable from weights when the brief is right. A search-enabled arm is a follow-up option, not part of this run.

**The four frozen definitions (D-arm input, verbatim):**

CONCEPT-1: This quantity is a number computed from three inputs: a starting belief expressed as a probability, a summary measure of how strongly a body of evidence leans toward or away from a claim, and a decision threshold — a probability above which one agrees to call the matter settled rather than open. It applies to a setting in which several sources each supply an evidence "lean" on a log-odds scale, those leans are averaged into a single average lean D̄, and a final belief is formed by adding a scaled version of that average to the starting belief on the log-odds scale: logit(p̂) = logit(π₀) + λ · D̄. Here λ is a free multiplier that sharpens the result when λ > 1 and softens it when λ < 1. This quantity is the specific value of λ at which the final belief exactly reaches the threshold, so that any larger multiplier declares the matter settled and any smaller one leaves it open. It has the closed form λ* = (logit(t) − logit(π₀)) / D̄: a ratio whose numerator depends only on chosen conventions (starting belief and threshold) and whose denominator depends only on the observed evidence. It is a tipping point, not a count of anything, and it is defined only when D̄ ≠ 0 and has the same sign as the numerator.

CONCEPT-2: This is a quantitative specification stating how accurate a measuring procedure must be before using its output is better than not using it at all. It applies wherever a pipeline needs a numeric setting — here, a multiplier that scales pooled evidence — and one may either estimate that setting separately for each case or fall back to a single fixed value used for every case. The specification's input is the error of the estimator, summarized as the root-mean-square error of the logarithm of the estimated quantity relative to its true value; its output is the fraction retained of the maximum achievable improvement in prediction accuracy, measured by a standard accuracy measure for probability forecasts. The stated content is a schedule: error ≲ 0.3 retains roughly 85% of the available gain; ≈ 0.6 retains about half; beyond ≈ 1.0 the estimator is actively harmful, producing worse predictions than the fixed fallback because its noise manufactures unwarranted confidence. Two conditions matter. First, the benchmark must be named: a fixed value chosen by fitting to already-resolved cases is a strong competitor but is unavailable when no resolved outcomes exist, in which case the honest comparison is against a merely assumed value. Second, the schedule is established by injecting synthetic errors of a given size rather than by running any particular estimator, so it characterizes an error level, not a method.

CONCEPT-3: This is a claim about where a loss of quality arises within a two-stage procedure. In such a procedure, a rater first generates candidate answers or interpretations for an item, then applies a filter — a rule deciding whether to commit to one candidate or to withhold and hedge. Observed performance is worse than some attainable benchmark, and one wants to know which stage is responsible. This claim asserts that the generation stage is not the culprit: the needed material is present in what the rater produces, and the shortfall lies downstream, in how that material is filtered or thresholded. Evidence for it takes the form of showing the same rater, on the same items, producing rich candidate sets (for example, multiple defensible readings on about three-quarters of ambiguous items) while its filter commits narrowly (hedging only about a third of them), so richness and strictness coexist within a single pass. The claim is stated with explicit limits. It is supported by frozen, pre-registered comparisons — for instance, a performance gap of at least 0.10 on a fixed metric, required to reproduce on a held-out split. Its scope is restricted to the filter rules actually tested: no fixed re-thresholding of the rater's stated confidences transferred out of sample, and no assertion is made about untested filter families or about quantities never manipulated.

CONCEPT-4: This is a procedure for extracting an answer from raters by using everything they put forward, rather than only their final pick. Its input is, for each item, one or more raters operating under a contract that asks each to list every defensible candidate answer in a fixed line format — one line per candidate, with a short paraphrase — with an explicit instruction not to pad the list, and in some versions with no request for a single final choice at all, so that the list itself is the response. From each rater one forms a candidate set S(item): the deduplicated collection of labels attached to its listed readings if it listed several, or the single label it chose if it committed to one. These sets are then pooled across raters — typically by union — and a simple fixed rule, decided in advance, selects one label from the pooled set. The output is a single answer per item, produced at full coverage: every item receives a decision. The procedure's point is comparative: applied to the same raters and items, it can match or beat the accuracy of the best individual rater, whereas pooling only the raters' committed single answers by voting can fall well short of the best member. It applies wherever raters can be instructed to list alternatives and their listed material is recorded.

### 7.3 The findings that matter (beyond the predictions)

**(i) The definition layer's value is inversely proportional to the coinage's semantic transparency.** Opaque coinages (C2's "operating requirement", C1's bare symbol): definitions took the D-arm to L3-exact/coherent-family while control was actively *misled* by the coinage's surface words (audit→accounting, cold-start→recommenders) — the raw term is not just uninformative, it steers wrong. Transparent slogans (C3 "the signal, not the cut"): the slogan alone carried the concept — both control draws hit Murphy 1973, and K-opus added Blackwell's comparison of experiments with the gloss "a less-informative signal cannot be rescued by any decision rule — essentially your bottleneck claim proved," which is the sealed key's own sufficiency territory, reached from fourteen words of gloss. A real pipeline should therefore triage coinages by opacity before spending definition effort.

**(ii) The sealed answer key was the weakest link — and the pipeline exposed it.** The key came from the project's own glossary (rows marked UNVERIFIED). The frozen definitions, faithful to the pre-07-13 excerpts, describe: C1 as a threshold-crossing tipping point (not an effective count — the definition even says "not a count of anything"), C4 as set-union pooling mechanics (not feedback formats). The draws named owners that fit *that* content: C1 → weight of evidence (Good/Turing), reverse-Bayes/switching value (Matthews), Wald's sequential-analysis ASN logic, extremization coefficients (Baron/Satopää 2014) — convergent across all three D-draws; C4 → set-level multiple-classifier combination with **Ho, Hull & Srihari 1994 named independently by two draws** (both flagging "their union-of-candidate-sets construction may substantially preempt this — verify"), approval voting (Brams & Fishburn) by all three, plus ROVER, premise-vs-conclusion-based judgment aggregation (K-opus), and process-vs-outcome supervision (K-sonnet). ALL of these are **unverified candidates** (same-family caveat: 2-3 Claude draws agreeing ≈ shared corpus, not confirmation) — but if Ho et al. 1994 survives a primary read, the definition pipeline found a closer owner for the enumeration protocol than three human-audited prior-art passes put in the glossary. That is the demo, and it is also a correction burden: the glossary's C1 and C4 rows need re-examination.

**(iii) The pipeline can silently invert a concept — definitional drift is real and needs a round-trip check.** The project's C3 says the *signal* (credence level) is the bottleneck and re-thresholding recovers nothing. The generated definition collapsed the three-stage picture (generate → assign credence → gate) into two (generate → filter) and asserted "the shortfall lies downstream, in how that material is filtered or thresholded" — which several draws then read, faithfully, as *blaming the cut* (D-opus: "the threshold rather than the generator is blamed"), the polarity opposite of the project's claim. The naming was correct for the definition and wrong for the concept. Any production pipeline needs a round-trip fidelity check: does the generated definition entail the original claim, as judged against the source excerpts?

**(iv) Abstraction trades domain neighbors for field neutrality.** The defgen constraint stripped AI/LLM context (by design); the control glosses leaked it ("judge credences," "panel"). Result: K-sonnet correctly sniffed the home field ("all four have a strong LLM-as-judge panel flavor, 2023–2025 vintage") and named process-vs-outcome supervision (Lightman et al.) — a live modern neighbor no D-draw could reach because the definitions hid the domain. A real pipeline should search *both* keys: the abstracted definition (for cross-field owners) and a domain-tagged variant (for the contemporary literature).

**(v) Epistemic hygiene was promptable and held.** All five runs hedged uncertain citations explicitly, several proposed "verify first" experiments, and two spontaneously stated the idiolect thesis itself (K-opus: "private coinages for century-old concepts cost you reviewers and make the prior art invisible to your own future search"). Zero detected fabrications, versus five caught in the search-based passes earlier this session — consistent with fabrication entering via search-snippet laundering rather than weights recall, though this experiment cannot separate that from the hedging instruction.

### 7.4 Verdict and limitations (revised per Codex review — the first draft said "validated," which overclaimed)

**Exploratory support, strong on exactly one cell.** C2 is the only concept where treatment and control demonstrably represented the same construct and the arms cleanly separated: definitions → R&S 1961 L3-exact twice, raw coinage → L0 with the coinage words actively steering control into the wrong fields. That single cell is real, survives draw-matching, and is the demo receipt. The other three cells are confounded — C1 and C4 by construct drift between the definition and the control gloss plus an admittedly mis-mapped key (§7.3-ii), C3 by definition-polarity inversion (§7.3-iii) — so they support no arm-level claim in either direction; per Codex finding 1, differences there may reflect changed meanings, not definition mediation. The primary endpoint, scored against a provisional internal glossary with only one primary-verified row, measures *agreement with that glossary*, not recovery of ground-truth owners (Codex finding 2) — and R&S 1961 specifically owns the VoI question-type, not the project's RMSE schedule.

**What survives without qualification:** the coinage-steering phenomenon (control's wrong-field pulls are visible in the raw outputs regardless of any key); the opacity-gradient reading of §7.3-i as a hypothesis for the next run; the candidate-owner slates (unverified); and the process findings (drift, abstraction trade-off, hedging discipline). **Before any public or FLF use beyond "exploratory demo with receipts":** verify the answer key against primary texts at claim level (starting with Ho, Hull & Srihari 1994 and the C&W/R&S rows), add the blinded round-trip fidelity gate, equalize draws, and rerun the three compromised concepts. Limitations stand as sealed (§4): n=4 concepts, one project, weights-only, single model family — and every new owner named here is **unverified until someone opens the primary**; an unread neighbor is not a neighbor.

### 7.5 Post-review verification: Ho, Hull & Srihari 1994, read in primary (2026-07-17)

**Obtained and read directly** (martinsewell.com mirror, 10pp PDF → pdftotext; *IEEE TPAMI* 16(1):66–75, Jan 1994). The two blind draws' recollection is **CONFIRMED with the correct scope**:

- **Verbatim, abstract:** *"An intersection method and a union method are proposed for class set reduction. Three methods based on the highest rank, the Borda count, and logistic regression are proposed for class set reranking."* And §II: *"In class set reduction, the objective is to extract a subset from a given set of classes, such that the subset is as small as possible yet still contains the true class."* §III: *"The second method computes the union of small neighborhoods taken from each classifier… a union of the neighborhoods for each training pattern always contains its true class."* Also: *"The union approach is preferred if the classifiers are specialized on different types of inputs."*
