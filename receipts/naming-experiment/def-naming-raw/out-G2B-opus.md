# Bottom line up front

**No single published system implements your exact three-part assembly.** The novel glue — a *coinage/new-sense detector as the trigger*, definitions written in a *constrained proper-name-free defining vocabulary*, and an explicit *"never materialize any global lexicon"* stance — I could not find assembled anywhere. What **does** exist, and is close, is a 2024–2026 cluster of **"generate-a-definition → embed the definition → retrieve/align by definition-similarity → assign a typed relation"** systems in ontology matching and cross-document scientific-concept coreference. The single closest is **SciCo-Radar (Forer & Hope, 2024)**, which generates context-dependent *and relational* definitions on the fly and uses them to infer equivalence + hierarchy across papers. Each of your three components is independently a decades-old named problem with a clear pre-2015 owner (Renouf 1993; Lesk 1986; Ogden 1930/West 1935; definition modeling's ancestor DEFINDER 2001). Your architectural stance (lazy, per-community, no global resource) is a known and named idea in a *different* field — **"pay-as-you-go" dataspaces (Franklin/Halevy/Maier 2005)** and **"emergent semantics" (Aberer & Cudré-Mauroux 2004)** — but has not, as far as I found, been articulated for *LLM-generated definitions*.

# Q1 — Closest published versions of the whole assembly

### SciCo-Radar — the closest single match
- **Owner + citation:** Lior Forer & Tom Hope, "Inferring Scientific Cross-Document Coreference and Hierarchy with Definition-Augmented Relational Reasoning," arXiv:2409.15113 (Sept 2024).
- **Verbatim (body):** "For each mention, we first create *singleton* definitions by retrieving relevant literature and using an LLM to generate context-dependent concept definitions. These definitions are used to augment the original inputs. We use the augmented input to train an LLM to detect cross-document coreference and hierarchy." — §1/§method.
- **Verbatim (body):** "Our approach, which we name SciCo-Radar (Scientific Concept Induction with Relational Definition Augmented Reasoning), uses automated generation of dynamic definitions of concept mentions based on their surrounding context, generated by retrieving literature full-text contexts or via GPT-4… We introduce *relational* definitions, which describe how two concept mentions are related or different."
- **Covers:** (2) auto-definition generation ✔ (context-dependent, on the fly); (3) definition-as-representation for finding the same concept across documents ✔, with **exactly your typed relations** — coreference (equivalent), parent/child (broader/narrower), and related ("*network embedding* belongs to a concept cluster that is a child of the parent concept *representation learning*").
- **Does NOT cover:** (1) no coinage/new-sense *detector* — mentions are pre-annotated; the definition is not written in a *constrained proper-name-free* vocabulary (quite the opposite — it injects retrieved literature and field context); operates over scientific papers, not "per community with no global resource" as a stated design principle (though its per-mention on-the-fly generation is *de facto* lazy/local).
- **Confidence:** High (opened in full).
- **Could not verify:** whether they ever store definition embeddings as a persistent index vs. compute pairwise at inference.

### GenOM — closest on components (2)+(3) in canonical terminology work
- **Owner + citation:** Yiping Song, Jiaoyan Chen, Renate A. Schmidt, "GenOM: Ontology Matching with Description Generation and Large Language Model," arXiv:2508.10703 (v1 Aug 2025; accepted *World Wide Web*, Springer, 2026).
- **Verbatim (body, prompt template):** "You are generating a definition for a concept from the {O_s name} ontology. The definition will be used to align it with candidate concepts in the {O_t name} ontology. You are a biomedical ontology expert. Your task is to generate a concise, alignment-friendly definition for a given biomedical concept…"
- **Verbatim (body):** "A candidate generation stage employs an embedding-based retrieval process to compute pairwise cosine similarities between source and target concepts using their enriched textual representations. Based on these similarity scores, the system retrieves the top-k candidate mappings for each source concept."
- **Covers:** (2) LLM generates a textual *definition* per concept ✔; (3) the *definition* (not the label) is embedded and used as the retrieval key ✔; typed relations ✔ ("formal relations such as equivalence… and subsumption, where one entity denotes a more general or more specific concept").
- **Does NOT cover:** (1) no coinage detection — it defines *all* existing ontology concepts, not newly-coined ones; the defining vocabulary is the **opposite** of constrained — the prompt deliberately injects proper names ("{O_s name} ontology") and field identity ("biomedical ontology expert"); it presupposes two *existing* global ontologies, i.e., it is the anti-thesis of "no global resource."
- **Confidence:** High (opened in full).
- **Could not verify:** exact relation-typing beyond equivalence in the released evaluation (Bio-ML track is equivalence-centric).

### LLMs4OM — the retrieve-then-match skeleton, but *without* generated definitions
- **Owner + citation:** Hamed Babaei Giglou et al., "LLMs4OM: Matching Ontologies with Large Language Models," arXiv:2404.10317, ESWC 2024 satellite events.
- **Verbatim (body):** "LLMs4OM employs a dual-module strategy: first, using the Retrieval-Augmented Generation (RAG)… for candidate selection for a given query C_source from a knowledge base of C_target, and then LLM-based matching, in a second module, for finer accuracy."
- **Verbatim (body):** "an embedding extractor model operates by extracting embeddings for C_target ∈ O_target and forming an embedding knowledge base… for a given C_s ∈ C_source… a C_s embedding is generated to calculate cosine similarity across all C_target, to identify top_k most similar candidates for alignments."
- **Covers:** (3) embed-then-retrieve-then-pairwise-verify skeleton ✔ (your "candidate matches then verified pairwise" is literally their two-module design).
- **Does NOT cover:** (2) — crucially, it embeds *concept / concept-parent / concept-children label representations*, **not generated definitions**. So it is your (3) without your (2). No (1); no constrained vocabulary; no lazy/no-global stance.
- **Confidence:** High (opened in full).

### MILA — same "retrieve-identify-prompt" family, efficiency-focused
- **Owner + citation:** "Ontology Matching with Large Language Models and Prioritized Depth-First Search," arXiv:2501.11441 (2025); reported top OAEI-2024 biomedical F1 in 4/5 unsupervised tasks.
- **What it is:** "a retrieve-identify-prompt pipeline within a prioritized depth-first search," consulting the LLM "only for uncertain mappings, while straightforward matches are resolved using fast lexical embeddings."
- **Covers:** (3) retrieval + pairwise LLM verification ✔; **does not** generate definitions as the key (2), no (1), no constrained vocabulary, no lazy/no-global framing.
- **Confidence:** Medium (read abstract + secondary summaries, not full body).

**Honorable mention / ancestor:** the original **SciCo** (Cattan et al., AKBC 2021, arXiv:2104.08809) established the *task* — "Hierarchical Cross-Document Coreference… induce clusters of context-sensitive mentions that co-refer to the same concept, and… deduce a hierarchy among these concept clusters" — i.e., your typed relations across communities, but *without* generated definitions (those are Forer & Hope's 2024 addition).

**Summary of coverage:** the field has (2)+(3) fused (GenOM, SciCo-Radar), (3) alone (LLMs4OM, MILA), and the typed-relation output (SciCo). Nobody bolts on (1) the coinage/new-sense trigger, nobody uses a *constrained defining vocabulary*, and nobody frames it as *lazy-per-community-no-global*.

# Q2 — Each component: field term + oldest owner

### (a) Detecting newly coined terms AND common words used in a novel project-specific sense
- **Field terms:** for the word-forms — **neologism detection** / **automatic term extraction (ATE)** (a.k.a. automatic term recognition); for the meaning shift — **novel word-sense detection / word sense induction (WSI) / lexical semantic change detection**. Your "common word used in a project-specific sense" is exactly what the sociolinguistic-NLP literature calls **community-/discipline-specific sense variation**.
- **Oldest owner (pre-2015):** **Antoinette Renouf, Project AVIATOR, 1993** — and it covers *both* halves of your (a). As summarized in the BCU/RDUES neology writeup and the 2026 neologism-pipeline survey: "Project AVIATOR (Renouf, 1993) was dedicated to testing the hypothesis that new words can be tracked by matching new items against existing lexical inventories, and new senses by matching new collocational profiles against existing ones." Also foundational: **Kageura & Umino (1996)**, the first ATE survey (linguistic vs. statistical term recognition); **Schütze (1998)**, "Automatic Word Sense Discrimination," *Computational Linguistics* 24(1) — the seminal unsupervised WSI method ("senses are interpreted as groups (or clusters) of similar contexts of the ambiguous word").
- **Modern owners of the exact "community sense" framing:** Lucy & Bamman, "Characterizing English Variation across Social Media Communities with BERT," TACL 2021 — "employing BERT to characterize variation in the senses of words… The specificity of different sense clusters to a community… is used to identify cases where a social group's language deviates from the norm" (abstract); and Lucy, Dodge, Bamman & Keith, "Words as Gatekeepers," ACL Findings 2023 — "we use word sense induction to also identify words that are widespread but overloaded with different meanings across fields" (abstract).
- **Confidence:** High on the taxonomy and owners; **could not verify**: I did not open Renouf 1993, Schütze 1998, or Kageura & Umino 1996 in full (facts/quotes are from secondary summaries and abstracts).

### (b) Automatic generation of definitions for terms
- **Field term:** **definition modeling** (generate a natural-language definition for a target word/embedding). Its data-mining ancestor is **definition extraction / automatic glossary construction**.
- **Owner:** Thanapon Noraset, Chen Liang, Larry Birnbaum, Doug Downey, "Definition Modeling: Learning to Define Word Embeddings in Natural Language," AAAI 2017 (arXiv:1612.00394) — "the task of generating a definition for a given word and its embedding." That names the task, but is post-2015.
- **Oldest owner (pre-2015 ancestor):** **Klavans & Muresan, DEFINDER, 2001** — "a rule-based system that mines consumer-oriented full text articles in order to extract definitions and the terms they define" ("Evaluation of the DEFINDER system for fully automatic glossary construction," JCDL 2001). This is *extraction*, not free *generation* — the honest caveat is that generation-from-scratch is genuinely a post-2015 idea; pre-2015 the field harvested definitions rather than composing them.
- **Confidence:** High that definition modeling = Noraset 2017 and that no clean pre-2015 *generation* owner exists; DEFINDER is the closest pre-2015 ancestor. **Could not verify**: full text of either opened.

### (c) Using the definition/gloss as the representation for matching/retrieval
- **Field term:** **gloss-based** (a.k.a. **gloss-overlap** / dictionary-based) matching; in ontology matching, **description/annotation-based matching** and specifically **"virtual documents."** Your "definition, not the term, becomes the search key" is precisely the gloss-based idea.
- **Oldest owner:** **Michael Lesk, 1986** — "Automatic sense disambiguation using machine readable dictionaries," SIGDOC '86 — the seminal use of dictionary **glosses/definitions** as the representation for matching: "the overlap of word definition… to disambiguate the word senses," selecting the sense whose gloss maximally overlaps the context. Extended by Banerjee & Pedersen (2003).
- **Ontology-matching owner (pre-2015):** **Qu, Hu & Cheng, "Constructing Virtual Documents for Ontology Matching," WWW 2006** — "a concept of virtual documents as a collection of weighted words that contains not only the local descriptions but also the neighboring information to reflect the intended meaning of the URIref," then compared by vector similarity. This is your (3) minus the LLM: descriptions-as-vectors as the alignment key.
- **Confidence:** High. **Could not verify**: Lesk 1986 and Qu 2006 opened in full (the Qu PDF is JS-only and would not render via safefetch; facts are from DBLP + search summaries).

### (d) Writing definitions in a constrained/controlled defining vocabulary
- **Field term:** **defining vocabulary** / **controlled defining vocabulary** (in lexicography); the broader engineering cousin is **controlled natural language** (e.g., Simplified Technical English).
- **Oldest owner:** **C. K. Ogden, Basic English, 1930** (an 850-word core meant to paraphrase anything), and the first *dictionary* actually built on the principle — **Michael West & James Endicott, *The New Method English Dictionary*, 1935**, "written using a defining vocabulary of just 1,490 words." The canonical modern instance is the **Longman Dictionary of Contemporary English (1978)** 2,000-word controlled defining vocabulary. The underlying principle is older still — as the Longman critique notes, it "goes back to Samuel Johnson's notion that words should be defined using 'terms less abstruse than that which is to be explained.'"
- **Confidence:** High (multiple corroborating sources; Longman/Wikipedia "Defining vocabulary" opened via search summaries). **Could not verify**: primary 1930/1935 texts not opened.

# Q3 — Is the "lazy, on-demand, per-community, no global resource" stance itself articulated anywhere?

**Yes — but in databases/semantic-web, not (yet) for LLM-generated definitions.** The stance has two named homes:

- **"Pay-as-you-go" data integration / dataspaces** — Franklin, Halevy & Maier, "From Databases to Dataspaces: A New Abstraction for Information Management," SIGMOD Record 2005; and Madhavan et al., "Web-scale Data Integration: You can only afford to Pay As You Go," CIDR 2007. The explicit design principle: move "away from the schema-first nature of traditional data integration," offer services "without any setup effort," and add semantic mappings "in an incremental and iterative manner… in a pay-as-you-go fashion." That is your "no global resource ever materialized; add relations on demand" stance, verbatim in spirit.
- **"Emergent semantics"** — Aberer, Cudré-Mauroux et al., 2004 — semantic interoperability "in a bottom-up, semi-automatic manner without relying on pre-existing, global semantic models," via "decentralized mappings" between peers. This is your "per community, no shared ontology, discover equivalences pairwise" stance.

**Where it is NOT yet articulated:** I found no paper stating the stance for *LLM-generated definitions specifically* — i.e., "don't build a global lexicon/ontology; lazily generate a gloss per project and match glosses." The closest *instantiation* (not manifesto) is SciCo-Radar's per-mention, context-dependent, generated-on-the-fly definitions — but they never frame it as an anti-global-resource design principle. So: the stance is **distinguishable and old** as a data-integration philosophy; applying it to *generated definitions as the pivot* appears to be the genuinely under-articulated (and possibly novel) part of your proposal.
- **Confidence:** High that dataspaces/emergent-semantics own the stance; Medium that no LLM-definition paper articulates it (absence-of-evidence — see coverage gaps). **Could not verify**: the CIDR 2007 PDF is JS-only and would not render; quotes are from search summaries and the Springer dataspaces chapters.
